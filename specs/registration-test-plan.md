# Тест-план: реєстрація нового користувача

## Application Overview

Перевірити форму реєстрації на https://qauto.forstudy.space/ відповідно до вимог зі скриншота: обов'язковість полів, правила для імені/прізвища, email і пароля, збіг паролів, стан кнопки Register та успішне створення користувача. Кожен сценарій починається з чистого стану та відкритої форми реєстрації. Для нового користувача використовувати унікальну адресу email з префіксом aqa-. Тестовий код не створювати.

## Test Scenarios

### 1. Реєстрація нового користувача

**Seed:** `tests/seed.spec.ts`

#### 1.1. REG-01 Успішна реєстрація з граничними коректними значеннями

**File:** `tests/registration/registration-positive.spec.ts`

**Steps:**
  1. Відкрити сайт із наданим доступом guest / welcome2qauto та відкрити форму Sign up → Registration.
    - expect: Відображається форма з полями Name, Last name, Email, Password, Re-enter password і кнопкою Register.
  2. Ввести Name із 2 англійських літер, Last name із 20 англійських літер, унікальний email формату aqa-<унікальне-значення>@test.com, пароль із 8 символів, що містить велику літеру, малу літеру та цифру; повторити пароль.
    - expect: Поля приймають дані, помилок валідації немає, кнопка Register активна.
  3. Натиснути Register.
    - expect: Користувача створено; застосунок підтверджує успішну реєстрацію або переводить до відповідного післяреєстраційного стану.

#### 1.2. REG-02 Перевірка обов'язковості всіх полів

**File:** `tests/registration/registration-required-fields.spec.ts`

**Steps:**
  1. Відкрити форму Registration та залишити Name, Last name, Email, Password і Re-enter password порожніми.
    - expect: Форма відображається у початковому стані.
  2. Перевірити валідацію форми та стан кнопки Register.
    - expect: Для Name показано Name is required, для Last name — Last name is required, для Email — Email required, для Password — Password required, для Re-enter password — Re-enter password required.
    - expect: Поля з помилками мають червону рамку; кнопка Register неактивна.

#### 1.3. REG-03 Перевірка правил Name і Last name

**File:** `tests/registration/registration-name-validation.spec.ts`

**Steps:**
  1. У відкритій формі перевірити Name і Last name окремими спробами: ввести неанглійські символи; значення довжиною 1 символ; значення довжиною 21 символ. Перевірити також коректні англійські значення довжиною 2 та 20 символів і значення з пробілами на початку/в кінці.
    - expect: Неанглійські символи та значення поза діапазоном 2–20 відхиляються з відповідною помилкою; рамка невалідного поля червона, Register неактивна.
    - expect: Значення довжиною 2 та 20 символів проходять валідацію.
    - expect: Пробіли на початку та в кінці обрізаються за допомогою trim і не враховуються при перевірці довжини.

#### 1.4. REG-04 Перевірка формату email

**File:** `tests/registration/registration-email-validation.spec.ts`

**Steps:**
  1. Заповнити інші обов'язкові поля валідними значеннями, а в Email по черзі ввести некоректні формати: без символу @, без локальної частини та без домену.
    - expect: Для кожного некоректного формату показано Email is incorrect; email-поле має червону рамку, кнопка Register неактивна.
  2. Замінити значення на валідну унікальну адресу з префіксом aqa-, наприклад aqa-<унікальне-значення>@test.com.
    - expect: Email проходить стандартну валідацію; помилка формату зникає.

#### 1.5. REG-05 Перевірка довжини та складу пароля

**File:** `tests/registration/registration-password-policy.spec.ts`

**Steps:**
  1. Ввести паролі довжиною 7 і 16 символів, зберігаючи наявність великої літери, малої літери та цифри.
    - expect: Паролі поза діапазоном 8–15 символів відхиляються, показується помилка, рамка поля червона, Register неактивна.
  2. Окремо перевірити пароль довжиною 8–15 символів без цифри, без великої літери та без малої літери.
    - expect: Кожен пароль, у якому бракує обов'язкового типу символу, відхиляється з помилкою; поле має червону рамку, Register неактивна.
  3. Ввести пароль довжиною 15 символів, що містить велику літеру, малу літеру та цифру.
    - expect: Пароль проходить валідацію.

#### 1.6. REG-06 Перевірка невідповідності паролів

**File:** `tests/registration/registration-password-mismatch.spec.ts`

**Steps:**
  1. Заповнити всі поля валідними значеннями, але в Re-enter password ввести значення, відмінне від Password.
    - expect: Для повторного пароля показано Passwords do not match; поле має червону рамку, кнопка Register неактивна.

#### 1.7. REG-07 Перевірка обов'язковості повторного пароля

**File:** `tests/registration/registration-confirm-password-required.spec.ts`

**Steps:**
  1. Заповнити Name, Last name, Email і Password валідними значеннями, залишивши Re-enter password порожнім.
    - expect: Для Re-enter password показано Re-enter password required; поле має червону рамку, кнопка Register неактивна.

#### 1.8. REG-08 Перевірка стану кнопки Register при виправленні помилок

**File:** `tests/registration/registration-register-button-state.spec.ts`

**Steps:**
  1. Відкрити чисту форму та заповнити всі поля коректними значеннями, крім Email, у якому вказати некоректний формат.
    - expect: Кнопка Register неактивна, email-поле позначене помилкою.
  2. Замінити Email на валідну адресу з унікальним префіксом aqa-.
    - expect: Після виправлення останньої помилки кнопка Register стає активною.
